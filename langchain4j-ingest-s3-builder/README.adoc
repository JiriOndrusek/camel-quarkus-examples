= LangChain4j Ingest: an S3 bucket as a knowledge base, declared in Java

The `langchain4j-ingest-quickstart` example declares its pipeline in
`application.properties`. This example declares the *same model in Java*, with the `@Ingest`
builder and the Camel Endpoint DSL — the type-safe twin of the configuration, with every
component option completed by the IDE — and puts a Quarkus LangChain4j RAG assistant on top:

[source,java]
----
@Ingest("manuals")
IngestPipeline manuals() {
    return IngestPipeline.from(Source.endpoint(dsl -> dsl.aws2S3(bucket)
                    .region(region).accessKey(accessKey).secretKey(secretKey)
                    .deleteAfterRead(false).delay(2000))
            .documentId("CamelAwsS3Key")
            .idempotentRepository("manualsRegister")
            .idempotentRepositoryAutoCreate(true))
            .splitter(500, 50);
}
----

Object keys are the document ids: retrieval cites them, and the register deduplicates by them
— a re-listed object ingests once, first write wins. `deleteAfterRead(false)` matters: a
knowledge base reads its source, it does not consume it. The vectors live in pgvector (Dev
Services PostgreSQL in dev and test mode, zero setup), the embeddings come from a local ONNX
model — no API key, no network.

== Running

Start an S3-compatible store and create the bucket:

[source,shell]
----
docker run --rm -d -p 4566:4566 -e AWS_ACCESS_KEY_ID=test -e AWS_SECRET_ACCESS_KEY=test \
    --name ingest-s3 mirror.gcr.io/floci/floci:1.5.28

aws --endpoint-url http://localhost:4566 s3 mb s3://manuals
----

Start the application in dev mode:

[source,shell]
----
mvn clean compile quarkus:dev
----

=== Watch the bucket become searchable

[source,shell]
----
# upload a document
echo "The warranty period is twenty four months." > warranty.txt
aws --endpoint-url http://localhost:4566 s3 cp warranty.txt s3://manuals/warranty.txt

# search (give the pipeline a couple of seconds to pick it up)
curl "http://localhost:8080/search?q=How%20long%20is%20the%20warranty%3F"
----

Mind the semantics: the register deduplicates by object key, so *overwriting* `warranty.txt`
does not re-embed it — the first write wins and the overwrite is answered `skipped`. Streams
that carry updates need a version-aware document id (a key that changes with the content);
replace-on-edit and delete arrive with the synchronising engine in a later release.

== Ask the assistant (Quarkus LangChain4j RAG)

`ManualsAssistant` is a `@RegisterAiService` interface wired to `ManualsAugmentor` — the one
piece of RAG code, a `Supplier<RetrievalAugmentor>` reading the same embedding store and model
the pipeline writes with, so one embedding space serves ingestion and retrieval.

To see what RAG retrieves — the augmented prompt an LLM would receive — no LLM is needed:

[source,shell]
----
curl "http://localhost:8080/chat/preview?q=How%20long%20is%20the%20warranty%3F"
----

For real answers, run the chat model locally with https://ollama.com/[Ollama] and ask:

[source,shell]
----
ollama pull llama3.2   # once
curl "http://localhost:8080/chat?q=How%20long%20is%20the%20warranty%3F"
----

== Tests

`IngestS3BuilderTest` starts an S3 container, uploads objects and asserts the lifecycle: put →
searchable (and incorporated into the RAG prompt via `/chat/preview`), a second object →
searchable, an overwrite of an existing key → answered `skipped`, first write wins. No LLM is
involved. `ChatWithRealLlmTest` talks to a real model and is disabled unless one is
configured.

[source,shell]
----
mvn clean test
----
